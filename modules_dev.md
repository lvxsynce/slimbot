# modules_dev.md — модули Slim Bot

Документация для авторов модулей. Модуль — это `.py`-файл, который
подключатель отправляет боту в личку; модуль добавляет свои команды в
любые чаты, в inline-режим или обрабатывает сообщения сам.

```
/start → пришли .py-файл → бот проверит и подключит
/modules                    список и управление
/modules вкл|выкл ИМЯ
/modules перезагрузить [ИМЯ]
/modules удалить ИМЯ
/modules система            список системных команд
/modules отключить .ping    выключить системную команду себе
/modules вернуть .ping      включить обратно
```

---

## 1. Минимальный модуль

```python
# hello.py
from slimbot_api import command

MODULE = {
    "name": "Привет",
    "version": "1.0",
    "author": "vasya",
    "description": "Считает слова",
}


@command(".hello", aliases=(".прив",), desc="Считает слова в сообщении")
async def hello(ctx):
    words = len(ctx.args.split())
    return f"Слов: {words}"
```

Всё. Файл называется `hello.py`, отправлен в личку — команда `.hello`
работает в любом чате от вашего имени.

**Обязательно:**

* имя файла — латиница, цифры и `_`, до 32 символов (`my_module.py`);
* переменная `MODULE` — словарь (см. §3);
* хотя бы один `@command`, `@inline` или `router`.

---

## 2. Что модуль может

| Возможность | API |
|---|---|
| dot-команда в любом чате | `@command(".имя")` |
| dot-команда только в личке с ботом | `@command(".имя", paths=("bot",))` |
| inline-команда | `@inline("ключ")` |
| свой aiogram-роутер | `router = Router()` в модуле |
| состояние между вызовами | `ctx.state` |
| доступ к Telethon-клиенту | `ctx.client` |
| доступ к внутренностям бота | обычный `import` |

### 2.1 Доступ к «основному функционалу»

Модуль исполняется **в процессе бота**, поэтому доступно всё, что
доступно самому боту:

```python
from utils.storage import user_sessions, get_modules, save_modules
from utils.escape import esc
from utils.ai import translate          # если есть такой хелпер
from utils.telethon_manager import telethon_manager
from config import DATA_DIR

client = ctx.client                     # ваш Telethon-клиент
me = await client.get_me()              # стандартный Telethon API
```

Именно это и было целью: модуль может затрагивать основной
функционал, а не жить в отдельной песочнице.

**Чего делать не надо:** не импортируйте `handlers.commands.router` и не
регистрируйте на нём хендлеры. На родительском роутере любой
message-хендлер блокирует все `sub_routers` (см. `AGENTS.md`,
инвариант 1) — это ломало бы все команды бота.

## 3. `MODULE`

Словарь с метаданными. Обязателен: без него модуль не загрузится.

```python
MODULE = {
    "name": "Погода",          # заголовок, до 64 символов
    "version": "1.2",          # до 16 символов
    "author": "@vasya",        # до 64 символов
    "description": "Погода в городе",  # до 400 символов
}
```

Значения — **строковые литералы**. Они читаются через `ast`, без
исполнения кода, поэтому вычисляемое (`"name": get_name()`) не
поддерживается: на этапе проверки модуль ещё не должен выполняться.

## 4. `@command`

```python
@command(".note",                       # основная команда
         aliases=(".n", ".заметка"),    # дополнительные
         desc="Сохранить заметку",
         key="note",                    # ключ для `.note справка`
         paths=("telethon", "bot"),     # где работает
         rate=None)                     # бюджет rate-limit
async def handler(ctx: Context) -> str:
    ...
```

### 4.1 Имя команды

* всегда с точкой: `.note` или `note` (нормализуется);
* в нижнем регистре: `.Note` → `.note`;
* без пробелов и точек внутри: `.моя.команда` нельзя;
* до 32 символов;
* кириллица разрешена.

Ошибка в имени — это `ValueError` **на импорте модуля**, то есть
установка падает с внятным текстом, а не «молча не работает».

### 4.2 `paths`

| Значение | Где работает |
|---|---|
| `("telethon", "bot")` | везде (по умолчанию) |
| `("telethon",)` | только в чатах (нужна Telethon-сессия) |
| `("bot",)` | только в личке с ботом |

`("bot",)` полезно для команд, которые не должны выполняться от имени
вашего аккаунта в чужих чатах.

### 4.3 `rate`

Бюджет rate-limit: `"ai"`, `"network"`, `"heavy"`, `"anim"`, `"local"`
или `None` (по умолчанию — без ограничения). Если модуль делает
сетевые запросы — укажите `"network"`, иначе один юзер сможет
завалить бота.

Параметр сохраняется на хендлере (`fn._module_rate`). Бот читает его
при вызове: команда проверяется тем же гейтом, что и встроенные, но
не попадает в статический `utils/cmds.py` (тот остаётся листовым и
не знает про модули).

> **Важно.** Если модуль пишет свой aiogram-роутер (§8), ограничение
> не навешивается автоматически — вызывайте
> `utils.rate_limit_gate.check(head, uid)` сами.

### 4.4 Возвращаемое значение

В Telethon-пути (команда в чате) хендлер возвращает:

| Возвращаете | Что получит юзер |
|---|---|
| `str` | текст, перезаписанный на месте сообщения с командой |
| `None` или `""` | ничего не отправляется (команда «тихая») |

В aiogram-пути (личка с ботом) `str` отправляется новым сообщением,
`None` — ничего.

Форматируйте текст сами. Карточку удобно собрать так:

```python
from utils.escape import esc

return f"<b>{esc(ctx.args)}</b>"
```

Обязательно экранируйте всё, что пришло от юзера (`utils.escape.esc`) —
иначе можно сломать HTML-разметку сообщения.

## 5. `Context`

| Поле | Тип | Что это |
|---|---|---|
| `ctx.user_id` | `str` | ваш Telegram id |
| `ctx.args` | `str` | текст после команды: `.note купить хлеб` → `"купить хлеб"` |
| `ctx.argv` | `list[str]` | `ctx.args.split()` |
| `ctx.head` | `str` | команда в нижнем регистре: `.note` |
| `ctx.event` | `Message` / `InlineQuery` | исходное событие Telethon или aiogram |
| `ctx.client` | `TelegramClient` / `Bot` | клиент: в чащах — ваш аккаунт, в личке — бот |
| `ctx.module` | `ModuleInfo` | метаданные модуля |
| `ctx.meta` | `dict` | `name`, `title`, `version`, `author`, `description` |
| `ctx.state` | `ModuleState` | состояние (см. §6) |
| `ctx.thread_id` | `int` | id топика форума, `0` — не форум |

### 5.1 Помощники ответа

```python
await ctx.edit("текст")     # перезаписать сообщение с командой
await ctx.reply("текст")    # новое сообщение в тот же топик
reply = await ctx.reply_message()   # сообщение, на которое ответили
```

Возвращать строку из хендлера проще, и это основной путь. Помощники
нужны, когда ответов несколько или их надо отправлять с задержкой.

В Telethon-пути `ctx.edit` остаётся в топике форума автоматически;
`ctx.reply` использует тот же топик.

### 5.2 Разница двух путей

Один и тот же хендлер работает и в чатах, и в личке, но `ctx.event`
там разные объекты:

```python
if hasattr(ctx.event, "raw_text"):
    chat_id = ctx.event.chat_id          # Telethon
    thread = ctx.thread_id
else:
    chat_id = ctx.event.chat.id          # aiogram
```

aiogram-путь работает и **без Telethon-сессии** — модуль с
`paths=("bot",)` может работать вообще без подключения аккаунта.

## 6. `ctx.state` — состояние

Маленький JSON на пару (юзер, модуль). Переживает перезапуск бота.

```python
ctx.state.get("cursor", 0)     # значение или default
ctx.state.set("cursor", 42)
ctx.state.update({"a": 1, "b": 2})
ctx.state.delete("cursor")
ctx.state.all()                # копия всего
ctx.state.clear()              # стереть
```

**Значение изолировано по юзеру.** Счётчик модуля, установленного вами,
не увидит сосед, у которого тот же модуль: состояние лежит по ключу
`(uid, модуль)`.

Значения должны быть JSON-сериализуемыми: `str`, `int`, `float`,
`bool`, `list`, `dict`, `None`.

## 7. `@inline`

```python
from aiogram.types import InlineQueryResultArticle, InputTextMessageContent
from slimbot_api import inline

@inline("погода", aliases=("weather",), desc="Погода в городе")
async def weather(ctx):
    city = ctx.args or "Москва"
    return [
        InlineQueryResultArticle(
            id=f"weather-{abs(hash(city)) % 10000}",
            title=f"Погода: {city}",
            description="Нажми, чтобы отправить",
            input_message_content=InputTextMessageContent(
                message_text=f"<b>{esc(city)}</b>: +18, ясно",
                parse_mode="HTML",
            ),
        )
    ]
```

Вызывается как `@bot погода Санкт-Петербург`. Ключ берётся по **первому
слову** запроса, остаток — в `ctx.args`.

Требования к результату:

* вернуть **список** объектов `aiogram.types.InlineQueryResult*`;
* `id` — уникальный в пределах ответа, до 64 символов, иначе Telegram
  отвергнет весь ответ;
* вернуть `None` (или `[]`), если отвечать не хочется — тогда
  сработает встроенная справка бота;
* исключение внутри хендлера **не** показывается юзеру, а пишется в
  `bot.log`. Сами ловите ошибки и возвращайте карточку с текстом.

`cache_time` задаётся системой (`INLINE_CACHE_DEFAULT`).

## 8. Свой aiogram-роутер

**Изоляция работает и здесь.** Роутер подключается к цепочке один раз на
весь бот, поэтому каждый его хендлер накрывается фильтром по владельцу:
сообщения от других пользователей до модуля не доходят. Это проверяется
тестами, а не на словах — см. `tests/test_modules.py`
(`test_module_router_is_silent_for_other_user`).

Если нужны не dot-команды, а полноценные хендлеры aiogram:

```python
from aiogram import Router, F
from aiogram.types import Message

MODULE = {"name": "Меню", "version": "1"}

router = Router()


@router.message(F.text == "/меню")
async def menu(message: Message):
    await message.answer("Меню модуля")
```

Роутер подключается автоматически. Работает **только в личке с ботом** —
в чатах сообщения идут через Telethon и aiogram их не видит.

Модуль с `router` тоже обязан объявить `MODULE` (см. §3).

Правила:

* создавайте **новый** `Router`, не импортируйте `handlers.commands.router`;
* не забывайте `MODULE`;
* помните про rate-limit: сами вызывайте
  `utils.rate_limit_gate.check(head, user_id)`, иначе ваш хендлер
  окажется без ограничений;
* **не ловите события «на автомате»**. Хендлер с пустым фильтром
  (например, `@router.message()`) отработает для любого сообщения и
  остановит обход всей цепочки — после него не сработает ни одна
  команда бота и даже подсказка опечаток. Если хендлер иногда не
  нужен — поднимите `SkipHandler`, а не возвращайте `None`:

  ```python
  @router.message(F.text == "/меню")
  async def menu(message):
      ...
  ```

  Фильтр тут узкий и конкретный, поэтому такой хендлер безопасен.

* хендлер, который сам пишет в `ctx.state`, работает только у вас —
  состояние разделено по `(uid, модуль)`.

## 9. Конфликты с системными командами

Если команда модуля совпала с системной (`.ping`) или с командой другого
вашего модуля — бот **не отдаёт её молча**. После установки приходит
карточка с четырьмя вариантами:

| Вариант | Что происходит |
|---|---|
| **Оставить системную** | системная команда работает, модуль её не касается |
| **Заменить** | системная команда отключается вам, `.ping` уходит в модуль |
| **Своё имя** | бот спросит новое имя команды, конфликт снимается |
| **Откатить модуль** | модуль удаляется целиком |

Пока вы не выбрали вариант, **системная команда продолжает работать**.
Это осознанно: молчаливый перехват `.ping` был бы сюрпризом.

Переименование живёт в реестре бота, а не в вашем файле. Исходник
остаётся таким, как вы его прислали, — поэтому после `перезагрузить`
придётся снова выбрать «своё имя».

### 9.1 Отключение системных команд вручную

```
/modules отключить .love
/modules вернуть .love
```

Отключённая команда **молчит**: ни ответа, ни подсказки «возможно, это
`.love`?». Если её перехватит модуль — заработает модуль.

## 10. Изоляция: модуль принадлежит одной сессии

**Команда модуля работает только у того, кто его установил.**

* реестр индексов ключуется по `(команда, uid)`;
* `ctx.state` разделён по `(uid, модуль)`;
* один и тот же файл можно поставить нескольким людям — каждый
  получит свою копию и свои данные;
* одинаковое имя команды у двух юзеров — **не** конфликт: конфликт
  считается только внутри одного аккаунта.

Это не «почти изоляция», а требование: подсказка в вашей сессии не
должна появляться у другого человека.

## 11. Модель доверия

**Песочницы нет.** Модуль — обычный Python, исполняемый в процессе
бота, с полным доступом к `utils.*`, `handlers.*`, сессиям и данным всех
подключённых пользователей. Это осознанный выбор: задача модулей —
расширять функциональность, а не изолироваться от неё.

Что **не** защищает:

* модуль может прочитать `config.TOKEN`, файлы сессий и данные других
  пользователей;
* может уронить процесс (`os._exit`, бесконечный цикл без `await`);
* может занять CPU и память.

Что **защищает**:

| Механизм | Что делает |
|---|---|
| `MODULE_ALLOWLIST` | кому вообще можно ставить модули. Проверяется в трёх точках: загрузка, вызов хендлера, UI |
| `MODULES_MAX_FILES` | сколько модулей у одного юзера (по умолчанию 5) |
| `MODULES_MAX_BYTES` | потолок на размер `.py` (по умолчанию 256 КБ) |
| `MODULES_COMMAND_TIMEOUT` | обёртка на вызов хендлера (по умолчанию 60 с) |
| `MODULES_ENABLED=0` | выключить подсистему целиком |
| AST-проверка | синтаксис и конфликты — **до** первого исполнения |

Для публичного бота `MODULE_ALLOWLIST` обязателен:

```
MODULE_ALLOWLIST=111111,222222
```

Пустой список — открытый режим (в лог пишется WARNING). Это ровно как
`SESSION_ALLOWLIST`: пустой список удобен для себя и опасен для всех.

Вывод: **ставьте только тот код, который написали или прочитали сами.**

## 12. Чего делать нельзя

| Нельзя | Почему |
|---|---|
| `@router.message()` без фильтра | отработает на любом сообщении и остановит обход всей цепочки: перестанут работать и команды бота, и подсказки опечаток. Не сработало — поднимите `SkipHandler` |
| Блокировать event loop (`time.sleep`, тяжёлый CPU) | заблокирует весь бот. Тяжёлое — в `asyncio.to_thread` |
| `await` без `asyncio.wait_for` на сети | хендлер обёрнут таймаутом, но ваши внутренние вызовы — нет |
| Регистрировать хендлеры на `handlers.commands.router` | сломает все команды бота |
| Экранировать HTML вручную тегами вокруг `ctx.args` | сломает разметку. Используйте `esc()` |
| `id` inline-результата из `hash()` без модуля | коллизии → `BadRequest` на весь ответ |
| Хранить секреты в исходнике модуля | файл лежит на диске и переживает перезапуск |
| Ожидать, что модуль увидит сообщения в чатах | в чащах работает только Telethon-путь |
| Отправлять пустые `id` в inline | Telegram отвергнет ответ |

Тяжёлое — в поток:

```python
import asyncio

def heavy_cpu(n):
    return sum(i * i for i in range(n))

result = await asyncio.to_thread(heavy_cpu, 10_000_000)
```

## 13. Отладка

Всё пишется в `DATA_DIR/bot.log` под именем `utils.modules`:

```
modules: loaded notes for uid=700001 (dot=1 inline=1)
modules: timeout .slow after 60s (uid=700001)
modules: .broken failed (uid=700001)  + traceback
```

Ошибка хендлера показывается юзеру короткой карточкой
`[x] Ошибка модуля: RuntimeError: ...`, подробности — в лог.

Типовые проблемы:

| Симптом | Причина |
|---|---|
| «Модуль не заявил ни @command, ни @inline» | нет ни `@command`, ни `@inline`, ни `router` |
| «Нет переменной MODULE» | не объявлен `MODULE = {...}` |
| команда не появляется | модуль выключен (`/modules выкл`) или имя не прошло `CMD_RE` |
| работает, но не в том чате | стоит `paths=("bot",)` |
| `[x] Модуль не ответил за 60 с` | хендлер блокирует event loop |

## 14. Полный пример

```python
# tasks.py
import asyncio

from aiogram.types import InlineQueryResultArticle, InputTextMessageContent
from slimbot_api import Context, command, inline
from utils.escape import esc

MODULE = {
    "name": "Задачи",
    "version": "2.1",
    "author": "@vasya",
    "description": "Список дел на сегодня",
}

KEY = "tasks"


def _tasks(ctx: Context) -> list:
    return list(ctx.state.get(KEY, []))


@command(".todo", aliases=(".дела",), desc="Список дел", rate="local")
async def todo(ctx: Context):
    items = _tasks(ctx)
    arg = ctx.args.strip()
    if arg:
        items.append(arg)
        ctx.state.set(KEY, items[-50:])
        action = "добавлено"
    else:
        action = "всего"
    body = "\n".join(f"• {esc(i)}" for i in items) or "пусто"
    return f"<b>Дела ({action}): {len(items)}</b>\n{body}"


@inline("todo", desc="Список дел inline")
async def todo_inline(ctx: Context):
    items = _tasks(ctx)
    return [
        InlineQueryResultArticle(
            id="todo",
            title=f"Дела: {len(items)}",
            description=", ".join(items[:2]) or "пусто",
            input_message_content=InputTextMessageContent(
                message_text=f"<b>Дела ({len(items)})</b>\n"
                             + "\n".join(f"• {esc(i)}" for i in items),
                parse_mode="HTML",
            ),
        )
    ]


@command(".todo очистить", paths=("telethon", "bot"))
async def todo_clear(ctx: Context):
    ctx.state.clear()
    return "Список очищен"
```

## 15. Шпаргалка

```python
from slimbot_api import command, inline, Context, on_message
```

| Что | Как |
|---|---|
| dot-команда | `@command(".x", aliases=(".y",), desc="…", paths=("telethon","bot"), rate=None)` |
| inline-команда | `@inline("ключ", aliases=("k2",))` → список `InlineQueryResult*` |
| аргументы | `ctx.args` (строка), `ctx.argv` (список) |
| состояние | `ctx.state.get/set/update/delete/all/clear` |
| ответить | вернуть `str`; или `await ctx.edit(...)` / `await ctx.reply(...)` |
